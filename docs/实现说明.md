# 实现说明

## 1. 目标与范围

把 `yunmei-four-0.1.2-dev`（Android）中的登录与开门链路移植到 HarmonyOS NEXT，并按后续需求增加：

- 白色、简洁、毛玻璃质感的原生 UI；
- 桌面卡片内直接显示开门进度，点卡片不跳转应用；
- 多次重试、扫描回退、缓存凭据回退，降低开门失败率。

智控键双触不在范围内：华为公开 SDK 没有向三方应用开放智控键的注册、监听或动作绑定 API。

> 2026-10-29 Cloessy 改造：UI 已改为深蓝灰/骨白、局部圆环、长按登录/设置、上滑开门；新增 1×2 胶囊卡、双二维码支持、实况窗与智慧生活入口。界面与系统能力部分以 [Cloessy-新功能说明](Cloessy-新功能说明.md) 为准；本文以下协议、BLE 与后台卡片部分仍适用。

## 2. 运行时结构

```
桌面卡片按钮
  │ postCardAction(call, CardUnlockAbility, {yunmeiAction:'cardUnlock'})
  ▼
CardUnlockAbility（无页面）
  │ CardUnlockService
  │   ├─ 检查保存的账号 / 蓝牙权限
  │   ├─ AppModel.restore()（登录 + 学校 + 门锁）
  │   ├─ AppModel.refreshForUnlock()
  │   ├─ AppModel.unlockWithRetry()
  │   └─ 每个阶段 CardUpdater.updateForm → 卡片文字 + 四段进度
  ▼
桌面卡片直接显示进度与结果（不打开应用）

正常应用入口
EntryAbility → Index
  ├─ 登录页（LoginPanel）
  └─ Tabs 白色主界面（系统毛玻璃底栏）
       ├─ 开门（UnlockPanel + UnlockSheet）
       └─ 我的（SettingsPanel）
```

`CardUnlockAbility` 的 `onWindowStageCreate` 不调用 `loadContent`，StartWindow 图标为 1×1 透明图、背景透明，因此不会显示应用页面或启动画面。`requestSuspendDelay` 申请短时后台任务，避免流程中途被挂起。

## 3. 卡片进度

卡片绑定数据：

| 字段 | 含义 |
|---|---|
| `lockLabel` | 当前门锁名称 |
| `statusText` | 当前阶段 / 结果文字 |
| `timeText` | 最近一次结果时间 |
| `online` | 是否已登录 |
| `step` | 0 空闲，1 刷新凭据，2 连接，3 订阅/发送，4 等待，5 完成，-1 失败 |
| `busy` | 是否正在开门（控制按钮 loading / 禁用） |

阶段映射：

- `PREPARING` → step 1（“正在准备/open 重试/网络异常使用缓存”）
- `CONNECTING` / `DISCOVERING` → step 2
- `SUBSCRIBING` / `SENDING` → step 3
- `WAITING` → step 4
- 成功 → step 5；失败 → step -1

两张卡片都用四段细进度条呈现 1→4，完成时全绿；失败时状态文字变红、进度条复位。

formId 由 `FormExtensionAbility.onAddForm` 写入 `filesDir/card_forms.json`（`CardRegistry`）。应用/后台 Ability 读取该文件并调用 `formProvider.updateForm`；文件跨进程可靠，不依赖 Preferences 的进程缓存。`CardUpdater` 在进程内用 Promise 串行化所有卡片更新，避免最终结果被较早的进度覆盖。

`CardUnlockAbility` 是 exported 的后台 Ability，因此卡片会携带 `cardToken`（首次启动生成的随机 UUID，保存在本机 Preferences）。`CardUnlockService` 先校验 token，不匹配直接返回，不会执行任何网络或 BLE 操作。

call 事件有两个硬性要求：`params.method` 必须存在，且提供方必须声明 `ohos.permission.KEEP_BACKGROUND_RUNNING`。卡片传 `method: 'unlockCard'`，Ability 在 `onCreate` 注册 `callee.on('unlockCard', ...)`，在回调里读取 RPC 参数中的 `cardToken` 并启动流程；缺少 method 时系统会直接忽略这次 call。

## 4. 网络与能力解析

`YunmeiApi` 逐条复刻 Android 客户端：

| 操作 | 服务器 | 路由 | 关键字段 |
|---|---|---|---|
| 登录 | base | `login` | `userName`, `userPwd` |
| 学校 | base | `userschool/getbyuserid` | `userId` |
| 型号表 | base | `locktype/all` | 空表单 |
| 门锁 | 学校 | `dormuser/getuserlock` | `schoolNo`, `userId` |

请求头同时携带 `token_userId` / `tokenUserId`、`token_data` / `tokenData`。响应包装兼容根数组、`data`、`list`、`result`、`o` 以及单元素数组。

> HarmonyOS 的 `ohos.net.http` 对空字符串 `extraData` 会抛 401 参数错误。`locktype/all` 是空表单 POST，因此统一带 `harmony=1` 标记字段，服务端忽略未知字段。

`LockCapabilities` 保留解析来源：

- `RESOLVED`：`aesSupport` 为 0/1、布尔值或可识别字符串；
- `OFFICIAL_NULL_AS_PLAIN`：字段存在但为 JSON `null`，按官方 `值 == 1` 的普通分支处理；
- `AES_FIELD_MISSING` / `AES_FIELD_INVALID` / `TYPE_NOT_IN_CATALOG` / `TYPE_ID_MISSING` / `TYPE_ID_INVALID` / `CATALOG_CONFLICT`：阻止发送。

## 5. 组帧与 BLE

普通帧：`D0 | len | ASCII(lockSecret) | A7`。

AES 帧：`D2 D3 | len | AES-128-CBC/PKCS7(内层 D0 帧, 固定应用 key/iv)`。

- `key = 94810265F7B0E3AC1A2DB50C0986374F`
- `iv  = 4DB8100EC7635A9F7D20035AB864CFE1`

BLE 流程：

1. 检查蓝牙已开启；
2. 有 MAC 直连；重试且上次是连接类失败时，按服务 UUID 扫描；扫描只接受 `connectable` 设备；
3. 连接超时 20 s，连接后等待 200 ms；
4. `getServices()` 最多 5 次、每次 4 s、间隔 350 ms；
5. 找服务、写入、通知特征；缺失时返回传输错误，允许上层重试；
6. 依据 `properties` 选 WRITE / WRITE_NO_RESPONSE、notify / indicate；
7. 订阅成功后等待 120 ms 再写入；
8. 20 字节分片，片间 120 ms；
9. 返回重组：`D2D3` 先解密再校验内层单帧；`A7` 动作确认、密钥错误、超时/断连分别归类；
10. `finally` 注销监听、断开、close。

## 6. 失败率优化

- **会话复用**：10 分钟内的 session 直接用于拉门锁；401/授权失效时自动重登一次再重试。
- **门锁复用**：15 秒内刚拉取的门锁跳过网络刷新；密钥被拒时 `refreshForUnlock(true)` 强制刷新。
- **三次尝试**：`unlockWithRetry` 最多 3 次 OPEN；连接类失败第二次改扫描连接，第三次直连；密钥被拒刷新凭据；单次超过 25 秒不再叠加下一次。
- **缓存凭据回退**：网络短暂异常且当前进程有 6 小时内获取的门锁凭据时，继续用缓存凭据 BLE 开门，并在进度/结果中提示“网络异常，使用上次门锁凭据”。
- **超时放宽**：连接 20 s、服务发现 4 s×5、写入 10 s、等待返回 10 s、分片间隔 120 ms。
- **诊断**：`BleUnlockService` 用 hilog 记录连接方式、结果类型与是否已写入；`YunmeiApi` 记录网络错误码。

## 7. 白色毛玻璃 UI

- 背景：白色 → 灰白渐变 + 低透明度薄荷绿/蓝色径向光晕；
- 卡片：`#F2FFFFFF` 半透明白 + `backgroundBlurStyle` + 1 px 白色高光边框 + 阴影；
- 底栏：ArkUI `Tabs`（`barPosition: End`）+ `barBackgroundColor('#D9FFFFFF')` + `barBackgroundBlurStyle(BlurStyle.COMPONENT_ULTRA_THICK)` + `barOverlap(true)`，两个页签「开门 / 我的」；
- 主按钮：薄荷绿→青色渐变圆形，深色锁图标；登录/结果按钮用墨色 (#101828) 主按钮；
- 文字：`#101828` / `#475467` / `#667085` / `#98A2B3` 四级；
- 动效：登录渐入、按钮按压缩放、开门按钮双层脉冲、旋转弧线、开门弹层阶段动画、结果图标回弹。

## 8. 数据

- Preferences（未加密）：账号、密码 MD5、学校编号、门锁编号、最近卡片状态/step/busy；
- 门锁密钥只在内存中，不持久化；
- 不记录密钥、token、完整帧到日志；
- `CardRegistry` 只保存 formId/formName，不含凭据。
